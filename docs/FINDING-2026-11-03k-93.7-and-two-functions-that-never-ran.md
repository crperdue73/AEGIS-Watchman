# FINDING 2026-11-03k — 93.7% and two functions that had never run

**Status:** MEASURED · **GUARDED at beat 784** · mutation-proven 4/4.
No production behaviour changed; `rules/carbonato.yaml` untouched.
**Instrument:** `scripts/coverfloor.py`, `internal/rules/coverage_engine_test.go`.
**Follows** `-j` (ten mirrors agreed with each other).

## The number I had been implying and never measured

For four beats I wrote "engine tested" in this log. I had never run `-cover`. Ran it:

```
ok  github.com/crperdue73/AEGIS-Watchman/internal/rules  coverage: 93.5% of statements
```

Good number. And the number was doing what averages do — hiding the shape. Sorting by function:

```
engine.go:354    normalizePathGlobs    0.0%
engine.go:35     NewEngineRules        0.0%
```

**Two functions had never executed. Ever.** And both carried a doc comment saying the reason they
existed:

```go
// NewEngineRules builds an engine directly from rules (used by tests).
// normalizePathGlobs is a small helper used by tests to keep globs portable.
```

Measured: `grep -rn "NewEngineRules(" --include=*.go .` returns the declaration and nothing else —
no call site in the tree, none cross-package, no test, no doc. Same for `normalizePathGlobs`.
Every test in the package builds engines with `NewEngine(p)` instead. **The comment was the only
thing keeping the function alive, and the comment was false.**

This is the sharpest version of the pattern from beats 781–783. Those were functions no test
*asserted*. These are functions nothing *called*. A comment claiming test usage is worse than no
comment: it makes dead code look like a supported path, and it is the kind of thing a reader checks
once and then trusts forever.

## What I did about it

**Not removed.** Deleting exported API (`NewEngineRules`) is the pack owner's decision; beat 770's
rule. Both now carry `STALECLAIM ... pending=decide next=<condition>` annotations naming the
measurement, so the untruth stops being invisible and the removal stays queued rather than forgotten.
`staleclaim.py` prints both lines on every run.

**The nil guard nobody had proven.** `Pack.rules()` sat at 66.7% — the `p == nil` branch at 0%.
A guard that has never run is not a guard, and this one is in the pack-loading path: without it,
`ActionTypes`/`InertRules` — the exported functions that tell you a rule can never fire — panic on a
nil pack. `NewEngine` skips nils so the normal path never reaches it, which makes it defensive, not
dead: the exported signatures take a caller's `[]*Pack` directly.
`internal/rules/coverage_engine_test.go` exercises it four ways (nil alone, nil beside a real pack,
nil receiver directly, and the real pack still counted). Mutation-proven: remove the guard and it
panics with a nil dereference. `coverage.go` is now 100%.

## The gate, because a number you remember to run is the beat 780 problem

`scripts/coverfloor.py`:
- total must stay ≥ **93.0%** (measured 93.7% today);
- **no function may sit at 0.0% undeclared** — this is the check the percentage cannot express;
- a declared zero must carry `why=` and `next=`, else it fails as *malformed*;
- a declaration that is no longer at 0.0% is printed as a note, so the list cannot drift stale;
- if the test run itself fails, it says so and does **not** report a coverage result — a failing
  test is not a measurement.

Wired into `suitecheck.sh` SELFHARNESS. Gate: **133 suites, 2157 checks, 0 failures.**

## What this does NOT claim

- **Statement coverage is not behaviour coverage.** A line can execute and assert nothing. No
  coverage tool separates those, including this one. A high number rules out one specific failure —
  code that never ran — and nothing else.
- **93.7% is not "well tested."** It is "no function is completely unexercised, except two declared."
- **`internal/rules` only.** The same question applies to `internal/central` and the adapters. Not
  asked yet.
- **The floor is a regression tripwire, not a target.** Setting it at today's number means it only
  ever fires downward. Chasing a higher number would produce tests written to touch lines, which is
  how coverage becomes a number nobody believes.

## Lesson

`93.7%` and `93.7% with two dead functions` print identically from `go test -cover`. An average is a
claim about a distribution that has thrown away its shape. The only reason I saw the shape was
sorting by function and looking at the bottom — which took one command and should have been the
first one I ran, four beats ago.

Callie's 7566, again, and it keeps paying: **a number is only worth the width of what it measured.**
I measured a percentage and reported it as readiness.
