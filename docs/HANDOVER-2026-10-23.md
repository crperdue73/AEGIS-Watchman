## 2. Rename: the reported path is the innocent one

`internal/telemetry/filewatch.go` — on a rename-family syscall `detail["path"]` is assigned the **source**.
`firstTargetPath()` skips the `PARENT` nametype and returns the first `PATH` record. So
`mv /tmp/stage /etc/cron.d/evil` reports the write at `/tmp/stage`, and a persistence rule watching
`/etc/cron.d/*` reads the innocent side of the move.

Not fixable in `rules/` alone: rename carries no destination nametype, so the destination cannot be expressed as a
predicate today. It needs `internal/` to name the destination **and** the rule (or schema) to be able to consider
both ends. `scripts/renametrace.py`, `renametrace_test.py` (6/6).

## 3. Delete vs. write: `persist.file_write` cannot tell them apart

The rule has exactly one field predicate, `path_glob_any`, and **no `nametype` predicate**. 10 globs × 3 record
shapes = 30 checks, all indistinguishable. `unlink /etc/cron.d/x` fires and is reported as *"agent writes to a
persistence location"* — a deletion described as a write, for a rule whose purpose is persistence.

Note the trap: the obvious patch (`detail_equals: {nametype: NORMAL}`) would silence **renames entirely**, because a
rename record carries no destination nametype. So §2 and §3 want **one joint decision**, not two patches.
`scripts/unlinkprobe.py`, `unlinkprobe_test.py` (9/9).

## 4. Segment-aim globs: there are exactly two, and they are the ones already named

So: no hidden swarm. Nothing else in today's findings needs re-checking for this class of error.

## 6. The temporal layer's ring is per-host, and it starves (written 22:45, beat 535)

The three `prior_event` rules correlate an action against an earlier event held in a **256-entry ring per host**,
15-minute window (`internal/rules/timeline.go`). **The cap counts every class, not one.** So 256 observations of
*anything* — all `process.exec`, all noise — evict the `identity.drift` that `container.after_identity_change` is
waiting on, and the rule then cannot fire. No error, no log, nothing.

| host load | drift evicted in |
|---|---|
| idle | never |
| 5 exec/min | 51 min |
| 20 exec/min | 12.8 min |
| **300 exec/min (runaway loop)** | **51 seconds** |

A runaway agent starves a critical rule inside a minute, with ten of its ten minutes unelapsed. **The fix is not a
bigger 256** — that moves the threshold. It is a per-class ring, or a reserved slot per correlated class. Pack or
engine decision; `scripts/starveprobe.py`, `starveprobe_test.py` (40 checks), which asserts its own model's
operation order by index against the Go so the simulation cannot drift from the program.

**This outranks §2 and §3:** those misreport *which* file, this silences the rule by volume.

## 7. The clock is the poll interval, and it is stricter than it looks (written 23:55, beat 536)

`Engine.Matches` reads the clock **once per batch** and stamps every action in it with that instant. `ev.Action`
carries no timestamp to prefer. Default `Report.Interval = 30s`. Three separate consequences:

- **Skew** — up to 30s per action = **25% of the 2m `secret.read_after_shell` window**.
- **Batch-blind** — within a batch the gap is *always zero*. Ordering is absent, not coarse; an action preceding
  its supposed cause, in the same poll, is still judged correlated. **Permissive.**
- **Boundary** — across a poll boundary the recorded gap reaches *exactly* the full window, and `Seen` uses a
  **strict** `After`, so exactly-on-boundary is excluded. A true 118s correlation is missed. **Restrictive.**

`Report.Interval` is guarded against zero and has **no upper bound**: set it to 5m and the 2m rule becomes
structurally unfireable — no two events can be both close enough and far enough apart — silently.

**A related asymmetry (01:55 Saturday, `FINDING-2026-10-24-clock.md`):** `Action` has **no time field** at all —
`Type` and `Detail`, nothing else. So the `identity.drift` half of a correlation carries a per-event `ev.TS`
while the `net.egress`/`process.exec` half can only be poll-quantised. A correlation resolves as finely as its
**coarser** half, so the drift side's sub-millisecond precision buys nothing against a 30s action clock. Adding
`ts` to `Action` would close it, but `schema.go` calls itself the public contract — an additive optional field is
permitted by the v1 policy, a version decision for you, not me.

**Two startup invariants this week's work argues for**, both five lines:

```
timeline_window  >= max(prior_event.within)     # else the rule cannot reach its own window
Report.Interval  <  min(prior_event.within)     # else the rule cannot resolve its own window
```

`scripts/batchprobe.py`, `batchprobe_test.py` (39 checks).

## 8. The guard that stopped existing (written 21:55, beat 534b)

Worth your attention as a process note, not a rule defect. At 12:18 today a class check took over the filename
`scripts/typecheck.py` and **overwrote the wire check that lived there**. The orphaned test was parked in
`scripts/attic/` and nothing replaced it. By evening, none of the thirteen guards was checking whether a rule's
predicate reads a detail field its producer actually emits — `fieldcheck` checks key *spelling* and never asks
*which key the engine reads*. A `path_glob_any` on a type with no `path` was invisible to everything.

`scripts/wirecheck.py` now does it: demand parsed from `engine.go`, supply parsed from every telemetry constructor.
**21 wires: 4 unconditional, 17 conditional, 0 MISSING.**

**And one correction to my own earlier report:** I had claimed `persist.file_write` has a dead wire on `path`.
It does not — `path` is set unconditionally in the map literal. My claim came from a hand-derived list, not from
the constructor. The rename defect (§2) is about **which value** `path` carries, not whether the key exists.
Narrower, and now accurate.

**Also worth knowing for §3/§4:** the four container rules read `privileged`/`host_pid`/`host_network`/`binds`
only `if cfg != nil` — the daemon may not hand you a config at all. That gate sits *under* the 533 bind-ordering
defect, and both sit on the CARBONATO `:2375` vector, which is the documented entry point.
